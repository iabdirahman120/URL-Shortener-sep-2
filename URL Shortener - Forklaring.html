📦 Hvad er projektet?

URL Shortener er en hjemmeside der tager en lang URL og giver dig en kort. Præcis som bit.ly eller t.ly.

Du besøger shr.dk, logger ind, indsætter en lang URL, og får fx shr.dk/r/abc123 tilbage. Når nogen klikker på den korte URL, sendes de automatisk videre til den lange.

ANALOGI
Forestil dig en garderobe på en restaurant. Du afleverer din store jakke (lang URL), og får et lille nummer (kort kode) tilbage. Når du vil have jakken igen, viser du nummeret, og de finder jakken til dig.

🏗️ Arkitektur — hvad taler med hvad?

Projektet er delt op i tre lag. De taler kun med hinanden på én måde — via HTTP requests.

🖥️ REACT (Frontend)
Kører i brugerens browser
↕
HTTP requests (JSON)
⚙️ EXPRESS (Backend)
Kører på DigitalOcean serveren
↕
SQL queries
🗄️ POSTGRESQL (Database)
Gemmer alle data permanent
VIGTIG REGEL
React taler ALDRIG direkte med databasen. Al kommunikation går igennem Express serveren. Det er en sikkerhedsregel — brugeren må ikke have direkte adgang til databasen.

🗄️ Database — PostgreSQL

Databasen er som et Excel-regneark der aldrig slukker. Den gemmer data permanent, selv hvis serveren genstarter.

ANALOGI

⚙️ Backend — Node.js & Express

Backend er "hjernen" i projektet. Den modtager requests fra React, behandler dem, og taler med databasen.

ANALOGI
Backend er som en tjener på en restaurant. Gæsten (React) bestiller mad (sender en request). Tjeneren (Express) går ud i køkkenet (databasen), henter maden, og bringer den tilbage.

Filstruktur

Be/
├── index.js ← Starter serveren, definerer alle routes
├── Db.js ← Forbindelsen til PostgreSQL
├── middleware/
│ └── auth.js ← Tjekker om brugeren er logget ind
└── routes/
    ├── auth.js ← Register og login
    └── urls.js ← Opret, hent og slet links

JWT Token — hvad er det?

Når du logger ind, får du et JWT token. Det er som et armbånd på en festival — du viser det ved indgangen (login), og så må du gå ind overalt bagefter uden at vise ID igen.

Bcrypt — hvorfor gemmes password ikke direkte?

SIKKERHED
Passwords gemmes ALDRIG som tekst i databasen. De krypteres med bcrypt til noget som:
$2b$10$xK9mN2pQ8rL3vT7wY1uZsO...

Selv hvis nogen stjæler databasen, kan de ikke se dine passwords.

🔐 Flow 1 — Bruger logger ind

Præcis hvad der sker trin-for-trin når du skriver email og password og trykker "Login".

1

Bruger skriver email + password i React

React gemmer det midlertidigt i state (computerens hukommelse mens siden er åben). Intet er sendt til serveren endnu.

2

React sender HTTP POST request til /api/auth/login

Email og password pakkes som JSON og sendes over internettet til Express serveren på DigitalOcean.

{ "email": "ahmed@email.com", "password": "hemmelig123" }
3

Express modtager requesten

Filen Be/routes/auth.js håndterer login. Den spørger databasen: "Findes denne email?"

// SQL query til PostgreSQL
SELECT * FROM users WHERE email = 'ahmed@email.com'
4

PostgreSQL finder brugeren og sender data tilbage

Databasen returnerer brugerobjektet inkl. det krypterede password.

5

Express sammenligner passwords med bcrypt

bcrypt sammenligner det indtastede password med det krypterede i databasen. Ingen af dem kan "dekryptere" det — bcrypt sammenligner på en matematisk måde.

6

Express genererer JWT token og sender det til React

Tokenet indeholder brugerens ID, og udløber efter 1 time.

{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }
7

React gemmer token i localStorage og sender brugeren til /dashboard

localStorage er browserens lille lagerplads. Token gemmes der så du forbliver logget ind selv om du refresher siden.

🔗 Flow 2 — Bruger opretter et kort link

Hvad sker der når du indsætter en lang URL og trykker "Opret link".

1

Bruger indsætter URL i dashboard og trykker "Opret link"

React sender en POST request til /api/urls/shorten. Den lange URL samt JWT token sendes med.

2

Express middleware tjekker JWT token

Filen Be/middleware/auth.js kører før alle URL-endpoints. Den læser tokenet og finder ud af hvem du er.

// Middleware — kører automatisk før alle /api/urls/ routes
const token = req.headers.authorization // "Bearer eyJ..."
const decoded = jwt.verify(token, JWT_SECRET)
req.userId = decoded.userId // fx 1 (Ahmed's ID)
3

Express genererer en kort kode

Hvis brugeren ikke har valgt et custom alias, genereres en tilfældig 6-tegns kode som abc123.

const short_code = custom_alias || Math.random().toString(36).substring(2, 8)
4

Express gemmer linket i PostgreSQL

INSERT INTO urls (original_url, short_code, user_id, expires_at)
VALUES ('https://youtube.com/...', 'abc123', 1, '2026-12-31')
5

Express sender det gemte link tilbage til React

React tilføjer det nye link til tabellen i dashboardet — uden at genindlæse siden.

↗️ Flow 3 — Besøgende klikker på kort link

Hvad sker der når nogen besøger shr.dk/r/abc123.

1

Besøgende besøger shr.dk/r/abc123

Browseren sender en GET request til Express serveren. Det kræver IKKE at man er logget ind.

2

Express slår short_code op i databasen

SELECT * FROM urls WHERE short_code = 'abc123'
3

Express opdaterer klik-tæller

UPDATE urls SET clicks = clicks + 1 WHERE id = 5
4

Express sender 302 Redirect til browseren

Browseren modtager en besked: "Gå til https://youtube.com/..." og sender brugeren automatisk videre. Alt dette sker på under 1 sekund.

🌐 Infrastruktur — hvad kører hvor?

DigitalOcean

  • Ubuntu server
  • Express backend
  • PostgreSQL database
  • Nginx webserver
  • PM2 procesvagt

Nginx

  • Modtager port 80/443
  • Serverer React filer
  • Proxyer /api/ til port 3000
  • SSL certifikat (HTTPS)

PM2

  • Holder Node.js kørende
  • Genstarter ved crash
  • Starter ved server reboot

Hvad sker der når du besøger shr.dk?

1

Din browser spørger DNS: "Hvad er IP-adressen på shr.dk?"

DNS svarer: 159.223.236.82 (DigitalOcean serveren)

2

Nginx modtager requesten på port 443 (HTTPS)

Nginx er det første der modtager alle requests. Den har SSL certifikatet fra Let's Encrypt.

3

Nginx beslutter hvad der skal ske

Hvis URL starter med /api/ eller /r/ → send til Express på port 3000.
Alt andet → send React's index.html fil.

4

React loader i din browser

HTML, CSS og JavaScript filer sendes til din browser. React starter og viser login-siden.
